# 方案 C：简化菜单项添加自定义命令流程

## 目标

将"添加自定义命令到菜单组"从 **7步跨2个标签页** 简化为 **1个对话框内完成**。

## 当前流程（7步）

1.  切换到"自定义命令"标签页
2.  点击"添加"，填写命令名称、系统命令、工作目录
3.  切换到"菜单配置"标签页
4.  选择菜单组
5.  点击"添加"
6.  手写 `RunCustomCommand("命令名称")`
7.  保存

## 新流程（1步）

1.  在菜单配置中点击"添加" → 在对话框内选择动作类型 → 选择/新建自定义命令 → 确定

## 实现步骤

### 步骤 1：改造 `MenuAddItem` 添加对话框

**文件：** `配置助手.ahk`

改造"添加菜单项"对话框的"功能/动作"区域：

- 新增 **"动作类型"** 下拉框（ComboBox），选项：`预设功能` / `自定义命令` / `启动程序`

- 选择 **"预设功能"** 时：显示当前的常用功能模板 ListBox（保持现有行为）

- 选择 **"自定义命令"** 时：

  - 显示"选择已有命令"下拉框（从 customCmdLV 读取所有已注册的命令名称）

  - 显示"新建命令"按钮 → 点击弹出子对话框（命令名称、系统命令、工作目录），确认后自动注册到 customCmdLV 并选中

  - 选中命令后自动填入名称和 `RunCustomCommand("xxx")` 动作

- 选择 **"启动程序"** 时：

  - 显示"程序名称"输入框

  - 显示"程序路径"输入框

  - 自动生成 `ActivateOrRun("名称", "路径")` 动作

- 隐藏原来的"功能/动作"手动输入框，改为只读显示自动生成的动作

**具体 UI 布局：**

```         
名称:          [__________]
图标:          [__________]
图标类型:      [emoji ▼]
动作类型:      [自定义命令 ▼]     ← 新增

--- 以下根据动作类型动态切换 ---

[预设功能时]
常用功能模板:  [ListBox...]

[自定义命令时]
选择命令:      [Playwright Show ▼]  [新建命令]
                                    ↑ 点击弹出子对话框

[启动程序时]
程序名称:      [__________]
程序路径:      [__________]

--- 始终显示 ---
生成的动作:    [RunCustomCommand("Playwright Show")]  ← 只读

[确定]  [取消]
```

### 步骤 2：实现动作类型切换逻辑

- 动作类型 ComboBox 的 `ChangeEvent` 回调中，根据选择显示/隐藏对应的控件组

- 使用 `ctrl.Visible := true/false` 控制控件可见性

- 预设功能模板的双击仍然自动填入动作

- 自定义命令下拉框选择后自动填入名称和动作

- 启动程序两个输入框内容变化时自动生成动作

### 步骤 3：实现"新建命令"子对话框

- 点击"新建命令"按钮弹出独立对话框

- 包含：命令名称、系统命令、工作目录（可选）

- 确认后：

  1.  将新命令添加到 customCmdLV
  2.  刷新"选择命令"下拉框的选项
  3.  自动选中新建的命令
  4.  自动填入名称和动作

### 步骤 4：改造 `MenuEditItem` 编辑对话框

编辑对话框也需要类似的改造：

- 根据当前 action 值自动判断动作类型（`RunCustomCommand` → 自定义命令，`ActivateOrRun` → 启动程序，其他 → 预设功能）

- 预填对应的控件值

- 切换动作类型时同样动态显示/隐藏控件

### 步骤 5：添加辅助函数

- `GetCustomCmdNames()` — 从 customCmdLV 读取所有已注册的命令名称，返回数组

- `BuildActionTypeUI(dlg, actionType, ae)` — 根据动作类型构建/切换 UI 控件

- `CreateNewCustomCmd(parentCb, ae, ne)` — 新建命令子对话框，注册后刷新下拉框

## 不需要修改的部分

- 主脚本 `CapsLock++.ahk` — 动作解析逻辑不变

- INI 文件格式 — 数据结构不变

- 自定义命令标签页 — 保留，用于批量管理命令

- 其他标签页 — 不受影响

## 风险点

- AHK v2 的 Gui 控件动态显示/隐藏需要注意布局，可能需要手动调整坐标

- "新建命令"子对话框是模态的，需要确保父对话框不被意外关闭
